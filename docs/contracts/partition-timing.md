# Contract: partition timing (socketed-XDC clock contract for DFX RMs)

**Version:** v0.1 (2026-07-07). Sibling to `partition-pins.md` (which fixes the
*structural* RP⇄shell boundary) — this doc fixes the *timing* boundary: the
exact clocks the static shell drives across the RP partition, and how each
reconfigurable module (RM) constrains its own internal timing so it can be
OOC-signed-off standalone AND link into the static without a pr_verify /
timing surprise. Widen only via the integrator (A6), re-reviewing both sides.

## Why this contract exists

Today the RMs OOC-synthesize with **zero** clock constraints and inherit every
clock from the static via partition pins at `link_design`/`read_checkpoint`
time. That is *sufficient* to route a config (the static's `create_clock` on
`OSCCLK1` propagates through the MMCM to `dut_clk`, and `build_dfx.tcl`'s guard
at ~line 238 refuses to implement an unconstrained design), but it leaves two
gaps:

1. **Each RM's internal timing is un-signed-off.** A standalone OOC
   `report_timing_summary` on an RM with no `create_clock` reports *"There are
   no user specified timing constraints"* — the RM's own register-to-register
   paths are never analyzed until they are already inside a full DFX
   implementation, which is the worst place to first discover a closure
   problem.
2. **RM-internal exceptions have nowhere to live.** An RM that generates its
   own divided clock (eth_ss's ÷2 MII clocks) or crosses clock domains
   internally (the MAC's WB↔MII async-FIFO boundary) needs `create_generated_
   clock` / `set_clock_groups` *scoped to that RM*. The static cannot author
   those — it does not know the RM's internal netlist — and they must survive
   into the linked implementation or `route_design` mistimes a genuinely-async
   internal crossing.

This contract closes both: it publishes the clocks the shell drives (so every
RM's OOC `create_clock` matches the static **byte-for-byte on period +
waveform**), and it defines a two-file per-RM XDC delivery so RM-internal
exceptions have a home.

## The clocks the shell drives across the RP boundary

All values are the **built** shell's (`fpga/shell/build_results_2026-07-07-256k/
post_impl_timing_summary.rpt` clock summary; generated by the shell BD's
`clk_wiz` cells, `fpga/shell/bd/shell_bd.tcl` SECTION 1). An RM sees a clock
here **only** on the partition-pin inputs it actually uses; everything else is
a data pin.

| RM partition-pin | Static clock object it carries | Period | Waveform | Freq | Source | DRP? |
|---|---|---|---|---|---|---|
| `dut_clk` | `clk_out1_shell_bd_clk_wiz_dut_0` | **20.000 ns** | `{0.000 10.000}` | **50 MHz** | `clk_wiz_dut` MMCM (`CLKOUT1_REQUESTED_OUT_FREQ 50.000`) | **yes** — DRP-reconfigurable (MMCM_DRP @ `0x44AB_0000`, `shell-regmap.md` v0.3) |
| `phy_rmii_ref_clk` | `clk_out2_shell_bd_clk_wiz_shell_0` | **20.000 ns** | `{0.000 10.000}` | **50 MHz** | `clk_wiz_shell` `clk_out2` | **no** — fixed RMII reference, never moves |
| `jtag_tck` | *(none)* | — | — | firmware-paced (kHz-class) | `jtag_bb` CSR bit (`0x44A7_0000`), bit-banged by `jtag_server` | n/a — **not a clock in the static** |
| `dbg_bscan_tck` | `u_shell/shell_bd_i/debug_bridge_0/inst/axi_jtag/inst/u_jtag_proc/tck_i_reg/Q` (generated, static BUFGCE) | **80.000 ns** | `{0.000 40.000}` | **12.5 MHz** | `debug_bridge_0` (mode 2) soft BSCAN, `m0_bscan` master; derived from `clk_out1_shell_bd_clk_wiz_shell_0` | **no** — but it toggles only while XVC shifts (gated during a swap by firmware) |
| `dbg_bscan_drck` | *(no clock object in the static; gated TCK, routed as a plain signal)* | 80.000 ns (OOC) | `{0.000 40.000}` | ≤ 12.5 MHz | same bridge, `m0_bscan_drck` | **no** |

Notes that bite if ignored:

- **`dut_clk` default is 50 MHz, but it is a *placeholder* (D12) and it is
  DRP-reconfigurable.** The RM `create_clock` MUST use whatever the static
  currently drives (20.000 ns today). If A6 retunes `clk_wiz_dut`'s default or
  firmware DRP-reprograms it, this table and every RM `_ooc.xdc` move together
  — that is the whole point of pinning the number in one contract. The RM's
  own frequency-dependent parameters (`rm_nanosoc`'s `UART_CLK_HZ`,
  `rm_eth_ss`'s `RTC_PERIOD_NS`) track the *same* number (both currently
  assume the wrong 25 MHz FPGA-proven operating point — flagged A6, orthogonal
  to the XDC period which tracks the *shell*).
- **`dbg_bscan_tck` / `dbg_bscan_drck` (2026-10 ILA mint) are declared in
  EVERY RM's `_ooc.xdc`**, 80.000 ns `{0.000 40.000}`, asynchronous to
  `dut_clk`, `phy_rmii_ref_clk` (and its generated clocks) and any OOC
  `jtag_tck`. OOC-only, like every row here: at link the static's generated
  TCK supersedes the port clock. In the static TCK is *derived from*
  `clk_wiz_shell`, the same MMCM as `phy_rmii_ref_clk`, so the two are not
  truly unrelated there; the OOC async group is a standalone-analysis
  convenience and the debug hub's own CDC owns the real crossing. Do NOT put
  them in an `_rm.xdc`. An RM with no hub also false-paths the data legs.
- **Name-collision trap.** `fpga/shell/constraints/mps3_harness.xdc` puts a
  `create_clock … -name dut_clk … [get_ports OSCCLK1]` on the **50 MHz board
  oscillator** — same English name, different clock object from the `dut_clk`
  *partition pin* (which is the MMCM output `clk_out1_shell_bd_clk_wiz_dut_0`).
  They happen to share the 20 ns period today (the MMCM is 50→50 MHz identity),
  but do not conflate them. An RM's `create_clock` is on its **`dut_clk`
  input port**, not on any board oscillator.
- **`jtag_tck` is not a clock in the static** (it replaced the retired
  `swd_clk` at the SWD->JTAG re-mint). It is a firmware bit-banged CSR
  pin (`JTAGBB`, `shell-regmap.md`), DC-slow, with **no `create_clock`**. An RM
  whose debug logic is genuinely clocked by it (nanosoc's SW-DP) MAY define a
  slow `create_clock` on it **in its `_ooc.xdc` only**, purely so the SW-DP's
  own registers get analyzed standalone; that clock has no static counterpart
  and must be declared asynchronous to `dut_clk` and must NOT appear in the
  `_rm.xdc` reapplied at link.

### The domain rule (restated from partition-pins.md)

`partition-pins.md` "Clock/reset domain rule": **all DUT clocks are generated
in the static shell; every crossing is CDC'd on the static side.** The timing
consequence: an RM's *boundary* data pins arrive already-safe (the static owns
`uart_bridge`'s async FIFOs, `board_gpio`'s synchronizers, the VPHY, the SWD
bit-banger), so an RM's `_ooc.xdc` should **false-path its async partition-pin
data ports** for standalone analysis rather than time them against `dut_clk`.
The only clocks that are *related* inside an RM are the ones the RM itself
derives (eth_ss's MII ÷2), and the only async crossings an RM must declare are
the ones *internal* to it (eth_ss's WB↔MII FIFO). Everything shell-side is not
the RM's timing concern.

## Per-RM delivery: two files

Each RM directory (`fpga/rp/<rm>/`) ships up to two XDCs:

### 1. `<rm>_ooc.xdc` — REQUIRED (standalone OOC timing sign-off)

Read by the RM's `ooc_synth.tcl` (guarded `read_xdc`, additive) so the staged
OOC `.dcp` carries real timing constraints. Contains:

- **`create_clock`** on every partition-pin clock **input** the RM uses, with
  period + waveform copied **byte-for-byte** from the table above (`dut_clk`
  always; `phy_rmii_ref_clk` iff the RM has a MAC; a slow OOC-only `jtag_tck`
  iff the RM has SW-DP logic).
- **RM-internal `create_generated_clock`** for any clock the RM derives
  (divided/toggled), sourced from the parent partition-pin clock.
- **`set_clock_groups -asynchronous`** for unrelated clocks the RM sees
  (`dut_clk` vs `phy_rmii_ref_clk`; `dut_clk` vs the OOC `jtag_tck`) and for the
  RM's own internal async crossings.
- **`set_false_path`** on the async partition-pin **data** ports (CDC'd
  static-side per the domain rule) so standalone `report_timing_summary`
  analyzes the RM's *internal* paths, not meaningless boundary paths.

This whole file is OOC-only: at DFX link every partition-pin clock **input**
is superseded by the static's propagated clock of the same period, and the
boundary false-paths are superseded by the static's own boundary constraints.

### 2. `<rm>_rm.xdc` — OPTIONAL (RM-internal exceptions that persist to link)

The **subset** of `<rm>_ooc.xdc` that must survive into the linked DFX
implementation because it describes the RM's *internal* netlist, which the
static cannot constrain:

- RM-internal `create_generated_clock` (the derived clocks).
- RM-internal `set_clock_groups` / `set_false_path` / `set_max_delay` on
  crossings **wholly inside** the RM.

It MUST NOT contain: any `create_clock` on a boundary clock input (the static
propagates those), any boundary-port false-path (the static owns the boundary),
or any reference to a shell/static object. Every object it names must resolve
**inside the RP cell**. An RM with no internal generated clocks and no internal
async crossings (e.g. a single-`dut_clk` RM like rm_nanosoc — its SW-DP is
bit-banged and un-clocked at link, its UART shim is single-domain) needs **no
`_rm.xdc` at all**.

## How `build_dfx.tcl` consumes these — ✅ IMPLEMENTED 2026-07-09

> **Status:** this was the "FOLLOW-UP — not implemented here" handshake. It is
> now wired into `fpga/dfx/build_dfx.tcl` exactly as specified below (see O3).
> The recipe is kept verbatim as the specification of what landed.

`build_dfx.tcl`'s `build_config` links an RM via
`read_checkpoint -cell [get_cells $rp_inst] $rm_dcp` (~line 215) and then
relies on the static's propagated clocks (~lines 217-242, the "Z2 lesson #1"
block + the clockless-link guard). The socketed-XDC addition is a single
guarded `read_xdc` **scoped to the RP cell**, applied right after the cell is
filled and before `opt_design`:

```tcl
# --- socketed RM-internal timing XDC (partition-timing.md) ------------------
# After read_checkpoint -cell fills the RP, reapply the RM's OWN internal
# timing exceptions (generated clocks, internal async groups) SCOPED to the
# RP cell. These describe the RM netlist the static cannot see; without them
# route_design mistimes RM-internal crossings (eth_ss's WB<->MII FIFO). The
# boundary clocks themselves still come from the static's propagation (the
# existing Z2-lesson-#1 block) — the _rm.xdc carries NO boundary create_clock.
set rm_xdc [file join $repo_root [rm_field $rm_key wrapper_dir] "${rm_key_short}_rm.xdc"]
# (rm_key_short: nanosoc/eth_ss — the RM's dir basename; rm_list.tcl already
#  stores wrapper_dir e.g. fpga/rp/eth_ss, so: file join $wrapper_dir <base>_rm.xdc)
if { [file exists $rm_xdc] } {
    puts "INFO: applying RM-internal timing XDC $rm_xdc scoped to $rp_inst"
    read_xdc -cell [get_cells $rp_inst] $rm_xdc
} else {
    puts "INFO: RM '$rm_key' ships no _rm.xdc (single-domain RM) — nothing to reapply"
}
```

Placement + ordering requirements for whoever wires it:

1. **After** `read_checkpoint -cell` (the cell must be filled so `-cell`
   scoping resolves the internal pins the generated clocks target) and
   **after** the static's clocks exist at the boundary (so a
   `create_generated_clock -source <rp>/phy_rmii_ref_clk …` inside the file
   finds its master).
2. **`read_xdc -cell [get_cells $rp_inst]`** — the `-cell` form roots every
   `get_pins`/`get_clocks` lookup inside the RP, so the RM's exceptions cannot
   accidentally touch static logic (matches how `dfx_floorplan.xdc` is scoped).
3. Reference config only vs every config: unlike the shell timing XDC (loaded
   once, then baked into `static_routed_locked.dcp`), the `_rm.xdc` is
   **per-RM** — apply it in `build_config` for **every** RM (both the
   `first_rm` reference path and the config-N path), because each RM has its
   own internal netlist. It is not part of the locked static.
4. `pr_verify` is unaffected: `_rm.xdc` adds only timing exceptions (no logic,
   no placement), so the reference and non-reference configs stay
   PR-compatible.

Until this lands, the RMs still link exactly as today (their internal
exceptions simply are not present at implementation — the same un-signed-off
state that motivated this contract, now at least *documented* and *validated
standalone*). The `_ooc.xdc` half is fully live now (staged into each RM's OOC
`.dcp` via `ooc_synth.tcl`).
