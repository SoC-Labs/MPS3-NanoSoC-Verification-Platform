# Files vendored from Harness Manager

The front panel's colours and status glyphs come from Harness Manager (HM), the
owner of the design tokens (HM decision P4/D4, `docs/design/CLCD_ALIGNMENT.md`
§4.1). The platform does not edit them. It re-vendors them, unchanged, when HM
changes them.

(2026-10-01 15:29 +0100, github SoC-Labs/HarnessManager), checked 2026-10-01
(`tools/gen_tokens.py --check`: ok).

the same 112 glyph bytes: compiled side by side, `memcmp` = 0 and both dumps hash

`source commit: a90e374a844b (+ changes to tools/gen_tokens.py not yet committed)`.
HM regenerated it from a clean commit in `4912af1`. The header now reads
`source commit: c74a1cfe734c`. That line is the only change: the glyph bytes and
the recorded glyph sha256 are the same. Re-vendored 2026-10-01 (lane PANEL-RC,
v2.0.0-rc2).

## How to refresh

1. In HM, run `python3 tools/gen_tokens.py --check` (it must say `ok`).
2. Copy both files unchanged:
   `cp <hm>/design/generated/clcd_palette.h <hm>/design/generated/clcd_glyphs.h firmware/clcd/`
3. Update the freshness line (HM commit) and the table (sha256, last-changed commit).
4. Run `make -C firmware/test test`. `test_clcd_golden` must still pass: the
   default theme never reads HM's palette or glyphs. `clcd.c`'s static assert stops
   the build if HM added or removed a role; place the new role in `PAL_TODAY` and
   `ROLE_NAMES` by hand. `clcd.c` includes `clcd.h` and `clcd_glyphs.h`, which
   both define `CLCD_GLYPH_OK`..`CLCD_GLYPH_DOT` with the same spelling: a code HM
   moves is a macro-redefinition error under `-Werror`.

## The drift gate

`tests/firmware_logic/test_clcd_hm_vendor.py` runs in `make check` and
`make check-ci`:
- It always checks both files against the sha256 pinned above.
- It always checks that `clcd_glyphs.h`'s glyph bytes still hash to the sha256 the
  header records, that `clcd.h`'s glyph codes equal the header's, and that no
  second glyph table exists under `firmware/clcd/`.
- With an HM checkout (`HM_DIR`, or `../harness-manager` beside this repo), it
  also compares both files with HM byte for byte. CI has no HM checkout, so there
  it runs only the checks above.

The LCD mirror's e2e oracle (`src/linux_harness/sw/harnessd/tests/lcdmirror_client.py`
`load_palette` / `load_font_ext`) reads these two files as text, never through
`clcd.c`.
