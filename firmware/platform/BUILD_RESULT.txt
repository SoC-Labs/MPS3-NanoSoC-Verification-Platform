WHAT CHANGED IN REV 4 (and why this file was rewritten, not appended to)
------------------------------------------------------------------------
rev 3 described a 256 KiB-LMB build with 4 KiB staging buffers, a 47,808 B
greybox blob and static_id 0xECCEDBF3. Every one of those numbers is now
wrong: LMB_KB defaults to 1024, the clearing buffers are 256 KiB each (which
is what keeps a swap off the shared QSPI part), the real greybox clearing is
61,704 B, and the minted/fielded static_id at the time was 0xA8C1C535. An evidence file
that is stale is worse than none, so it was replaced.

  1. PRODUCT=1 exists. It expands to CLCD=1 CLCD_KVM=1 HWICAP_FIFO=1
     WINDOWED=1 TOUCH=1 -- the set the FIELDED shell's firmware was built
     with (docs/FIELDED_SHELL.md, static_id 0xA8C1C535). Fabric pair:
     SHELL_TOUCH=1 on the bitstream build. Before it, that set existed only
     as five literals in a mint script and `make elf` with the DEFAULTS built
     an image that pings, reports the right static_id, passes every
     acceptance gate, and CANNOT LOAD A SINGLE RM (LITE HWICAP writers vs a
     FIFO shell).
  2. The Makefile now has consistency gates -- there were none before, and
     $(error) did not appear anywhere in it:
       TOUCH=1 without CLCD=1     -> $(error)   (used to die at LINK)
       CLCD_KVM=1 without CLCD=1  -> $(error)   (used to LINK and silently
                                                 never service the KVM)
       HWICAP_FIFO unset          -> $(warning) (LITE shells legitimately
                                                 exist; an error would be wrong)
     Skipped when the only goal is `clean`.
  3. -Werror on both the target build and firmware/test/. One carve-out,
     -Wno-error=cpp: a #warning is an author talking to a reader
     (net_if_lwip.c reports a BSP built without LWIP_TCP_KEEPALIVE, which the
     firmware build cannot correct). Three long-standing warnings were fixed
     with it: clcd.c's nested "/*", diag.c's volatile-discarding memset, and
     an unused variable in test_config_agent_keepalive.c.
  4. Dead code out of the image: coordinator_main_loop() DELETED (noreturn,
     compiled into every image, called by nothing -- main.c owns the real
     superloop), and swd_server.c gated behind LEGACY_SWD=1 (the JTAG cutover
     made jtag_server/6921 the live debug service; nothing on the target calls
     swd_server_*). The swd_server SOURCE stays: its host test links it.
  5. New `version` verb on 6900 (net-protocol.md v0.8) -- the running image
     reports its own harness release, HARNESS_VER32, build sha/dirty, the LMB
     size it was LINKED for, and its compile-time feature set.

Deliberate, not slack: the two buffers must COEXIST (the incoming clearing
sits in config_agent's slot while SWAP_STREAM_CLEARING replays the outgoing
one from swap_fsm's arena), and sizing them to hold the largest real clearing
is what keeps every swap QSPI-FREE. One physical 8 MiB part backs BOTH the
DFX overlay store and the nanoSoC boot map; D16 (ARCHITECTURE_SPEC.md §15)
says keep it idle. Gated by scripts/harness_gates/check_clearing_fits.py --
when it fires, RAISE the buffer, do not waive.
