# static_inputs.txt -- WHICH SOURCES DECIDE THE STATIC SHELL.
#
# Read by fpga/dfx/tools/static_canon.py, which hashes exactly the files this
# file declares into `static_canon` -- the CONTENT identity of the static,
# recorded beside `static_id` in mint.json.
#
# WHY THIS FILE EXISTS
# --------------------
# `static_id` is a CRC-32 of static_routed_locked.dcp, and a .dcp is a zip with
# embedded timestamps. So a rebuild from byte-identical sources mints a DIFFERENT
# static_id, and two questions have no answer anywhere:
#
#     "is this the same shell?"      -- the id says no even when nothing moved
#     "did anything actually change?" -- nothing on disk can say
#
# A hash over the INPUTS answers both. But a hash over inputs is only as good as
# the list of inputs, and a list of files is the classic place for a gate to rot
# quietly: a source file is added, nobody adds it here, and the hash goes on
# reporting "unchanged" forever. So this declaration is GATED, not trusted --
# see "The three rules" below.
#
# FORMAT
# ------
#   root    <dir>             a repo-relative DIRECTORY whose design-source
#                             files must ALL be accounted for (include or
#                             exclude), recursively. Not a glob: a plain prefix.
#   include <glob>            a file that DOES reach the static netlist -> HASHED
#   exclude <glob>  # reason  a file under a root that does NOT -> not hashed
#
# Globs are fnmatch against the full repo-relative path, and `*` matches any
# character INCLUDING `/`. One rule, no `**` subtleties: `fpga/dfx/rms/*` covers
# that whole subtree.
#
# PRECEDENCE: include beats exclude. That is what lets a broad exclude carry the
# rationale for a whole subtree while one file inside it is still hashed
# (fpga/dfx/rms/* vs rm_greybox, below).
#
# THE THREE RULES (static_canon.py check -- all three have a control in
# tests/dfx_flow/test_static_canon.py):
#   1. every `include` glob must match at least one tracked file. A glob that
#      matches nothing is a declaration that has silently stopped covering
#      anything, and it looks exactly like a healthy one.
#   2. every design-source file under every `root` must be matched by an
#      `include` or an `exclude`. An undeclared file is a hard failure naming
#      the file -- this is what stops the hash from rotting.
#   3. every `exclude` must carry a `# reason`. "Not hashed" is a claim about
#      the build, and an unexplained one is indistinguishable from an oversight.
#
# DESIGN-SOURCE EXTENSIONS (rule 2's scope): .sv .v .svh .vh .xdc .tcl .xml
# .yaml .yml. Anything else under a root is out of scope -- reports, READMEs,
# firmware C. Firmware is deliberately NOT here: it is baked in by `updatemem`
# AFTER place-and-route, so it changes the .bit without changing the netlist.
# That axis is HARNESS_VER32 / USR_ACCESS, not this one
# (docs/VERSIONING_PLAN.md §3.0).
#
# THE FILE SET IS `git ls-files`, i.e. TRACKED files only. An untracked source
# is unreproducible by definition; `sources.repo.dirty` in mint.json is what
# records that the tree had uncommitted content at all.

# `*` matches `/` here (see FORMAT above), so this ONE glob covers every CSR
# block's whole subtree: fpga/shell/ip/<block>/<anything>.sv. Two consequences
# worth stating, because both have been asked:
#   * dut_egress (2026-09-11, e2062c1) needed NO new line -- dut_egress.sv and
#     dutegr_cfifo.sv are already hashed, confirmed by `static_canon list`.
#   * a NEW block that ships only .sv under fpga/shell/ip/ needs no line either.
#     A new block that ships a .xdc, a .tcl, an .xci-generating script or a .yaml
#     under that tree DOES: those extensions are design sources (rule 2's scope)
#     and an undeclared one is a hard `canon-check` failure naming the file.

# `include` glob that matches no tracked file is a rule-1 failure, and a rule-1
# failure is indistinguishable from a declaration that has quietly stopped
# covering anything. That is the whole point of rule 1, so this stays a comment.
#
# WHAT IS ALREADY COVERED when they land, with no edit to this file:
#   * fpga/shell/ip/usr_access_rd/*.sv        -- by `include fpga/shell/ip/*.sv`
#   * the BD instantiation + address assignment -- by `include .../shell_bd.tcl`
#   * a Xilinx watchdog IP configured only inside shell_bd.tcl (no local RTL)
#                                             -- by the same shell_bd.tcl line
#
# WHAT NEEDS A LINE ADDED HERE, and the line to add:
#   * a constraint file shipped with the block:
#         include fpga/shell/ip/usr_access_rd/*.xdc
#   * a packaging or generation script shipped with the block:
#         include fpga/shell/ip/usr_access_rd/*.tcl
#   * the block living anywhere OUTSIDE the three declared roots (fpga/shell,
#     fpga/ethernet, fpga/dfx) -- then it needs a `root` line too, not just an
#     include, or rule 2 cannot see the directory at all.
#
# HOW TO KNOW WHICH: run `make -C fpga/dfx canon-check` after the block lands.
# It either passes (covered) or names the exact undeclared file. Do not guess,
# and do not pre-declare -- a glob added early fails rule 1 today and is then
# "fixed" by deleting it, which is how the real declaration gets lost.
